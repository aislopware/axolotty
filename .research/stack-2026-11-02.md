# Axolotty: chọn stack (2026-11-02)

Câu hỏi: AppKit + Zig có cho được hiệu năng tốt, chất lượng tốt mà dev loop không ngốn tài nguyên như slopty (Rust/GPUI) không?
Số đo thô nằm ở `bench/RESULTS.md` (M1 Max 32 GB, Zig 0.17.0, Swift 6.4.2, Xcode 27.2).

## 1. Bài học từ hai project trước

| | slop-desk (Swift/AppKit + ~85 crate Rust + libghostty-vt) | slopty (Rust thuần + GPUI) |
|---|---|---|
| Đau nhất | Hai ngôn ngữ cùng giữ logic, nên FFI và golden vector phải giữ cho khớp. Đã đổi hướng Rust→Swift rồi lại Swift→Rust (`docs/40`, `docs/55`). xcodebuild tốn ~85 s chỉ để "planning" dù không có gì thay đổi. Một lần build-for-testing iOS mất 25 phút, chạy trên đúng 1 core. | `target/` 117–212 GB, khoảng 130 GB mỗi ngày. Sửa 1 dòng mất 11–90 s. Gate mất 9.8 phút và 50 runner-phút. Load 25–90 trên 10 core. |
| Nguyên nhân gốc | Ranh giới giữa hai ngôn ngữ không cố định. Logic nằm rải ở cả hai bên. | 1.335 unit phụ thuộc (proc macro, build script, Zig của ghostty, Luau C++). 7 target triple. Mỗi lane/agent có một thư mục warm riêng. clippy pedantic+nursery trên mọi triple. |

Phần lớn chi phí của slopty là do **quy trình** (nhiều lane × nhiều triple × nhiều dependency), không chỉ do bản thân rustc.

## 2. Số đo trên máy này

| Vòng lặp | Sửa → build xong | Ghi chú |
|---|---|---|
| Core Zig của Ghostty (376k dòng), Debug | 27–40 s | Sửa gì cũng vậy, kể cả comment. Toàn bộ unit đi qua LLVM. |
| Core Zig của Ghostty, ReleaseFast | 96 s | |
| Test lib-vt, không lọc | ~2.5 phút compile + ~8 phút chạy | 7 GB RSS mỗi process |
| Test lib-vt, `-Dtest-filter` | 6 s | |
| Skeleton Swift/AppKit 5.5k dòng | 2.0–3.5 s | `swift build` và `xcodebuild` cho kết quả như nhau |
| App Ghostty thật (33.8k dòng Swift) | 7.8–10 s | Cold 26 s |
| File tổng hợp ~6k dòng: C / Rust / Zig / `zig -fno-emit-bin` | 0.68 / 1.6–2.1 / 2.6 / 0.24 s | |

Đĩa:
- `.zig-cache`: 1.4 GB sau lần build cold, mỗi lần sửa thêm 0.5–0.7 GB, không bao giờ tự GC.
- Swift `.build`: ~150 MB. DerivedData của Ghostty: 763 MB.

## 3. Sự thật về Zig 11/2026 (có nguồn)

- Bản mới nhất là 0.17.0 (2026-10-01). Chưa có ngày cho 1.0. Mỗi bản đều phá API:
  - 0.15: Writergate.
  - 0.16: `std.Io`; Ghostty port mất ~3 tháng, ~16k dòng.
  - 0.17: build system và `@cImport` bị bỏ; Ghostty port mất 19 ngày, ~6k dòng.
- Trên aarch64-macos, backend tự viết của Zig vẫn đang "in development" (treo khi build hello world). `-fincremental` có xuất binary thì panic `TODO(MachO2)`. Con số 975 ms Mitchell công bố là đo trên x86_64 Linux.
- Không có ASan cho code Zig. Bun đã rời Zig sang Rust (07/2026) vì lỗi use-after-free/double-free. Ghostty có advisory UAF ngày 2026-10-27.
- LLM viết Zig 0.17 kém (dùng API cũ). Zig upstream cấm đóng góp do AI viết. ZLS ra sau Zig vài tuần.
- `include/ghostty.h` (full surface) là API nội bộ. `libghostty-vt` chưa có tag và API "not yet stable". cmux giữ một fork với 78 patch và dùng xcframework prebuilt có pin checksum.

## 4. Kết luận

Swift/AppKit là ngôn ngữ chính. Ghostty là dependency dạng binary (xcframework pin checksum, chỉ build lại khi bump). Không có core Zig riêng lớn: chỉ viết native (C hoặc Zig) cho hot path đã đo được, mỗi phần là một artifact nhỏ, tách riêng.
