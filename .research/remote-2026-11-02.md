# Remote: design (2026-11-02)

**Where this comes from.** Research on:
- VS Code Remote-SSH, Dev Containers and Tunnels;
- Zed remote development;
- JetBrains Gateway;
- cmux (cmux-tui ≥ 0.65 and the legacy `cmuxd-remote`);
- herdr-core machines;
- Warp's SSH extension and Remote Control;
- iTerm2 `tmux -CC`;
- mosh and Eternal Terminal;
- Claude Code Remote Control, Happy and Termius;
- transports: Tailscale, Cloudflare Tunnel, WebRTC, and relays with end-to-end encryption.

Sources were retrieved 2026-11-02. They're listed at the end, with the key quotes.

**Two goals:**
- **(a) Remote Window.** A project whose sessions run, and keep running, on another machine (an ssh host, a container or a VM).
- **(b) Reach this Mac from elsewhere.** Another Mac, a phone or a browser can watch agents, answer them and type.

## (a) Remote Window

### Shape
- Every machine runs its own unchanged `axolottyd` and `axolotty-ptyd`.
- The app already has one `HostSession` per host. It just connects to more than one.
- Add `HostEndpoint.command(argv:label:)`. Examples:
  - `ssh -S <ctl> -o BatchMode=yes -o ClearAllForwardings=yes -o RemoteCommand=none -o RequestTTY=no -T host -- axolotty bridge`
  - `docker exec -i c axolotty bridge`
  - `kubectl exec -i pod -- axolotty bridge`
- `axolotty bridge` (about 150 lines):
  1. Find the runtime folder.
  2. Take an `flock`.
  3. If `d.sock` doesn't answer, start `axolottyd` detached (`setsid`).
  4. Splice stdin/stdout ⇄ `d.sock` byte for byte.
  5. Print a magic preamble first. The client discards bytes until it sees it, which skips ssh banners and rc files that echo (herdr #3789).
- Why stdio and not `ssh -L sock:sock`:
  - `AllowStreamLocalForwarding` is off on many servers (cmux).
  - `-L` can't start the daemon.
  - stdio also covers containers and cloud CLIs.
- This is the pattern Warp, Zed, cmux and herdr all use.

### Persistence
- The remote ptyd owns the PTYs, as cmux-tui and herdr do. Warp and Zed don't, and their remote shells die with ssh.
- When ssh drops, only the bridge dies. Redial, then `hello`:
  - same `epoch`: `attach(pane, have:)` resumes warm from the journal offset;
  - new epoch: resync from a snapshot.
- The newest bridge from the same client id replaces a half-open old one (cmux).

### Login
- "Connect to Host…" opens a real Axolotty pane running `ssh -S <private ctl> -o ControlMaster=auto -o ControlPersist=600 host exit`. That's herdr's `hc machine login`.
- Host keys, passwords, 2FA and FIDO touches are all answered there, by the person.
- Every later call is `BatchMode=yes` over that master.
- ssh exit 255 means `needsLogin`, with no blind retry (Warp, cmux).
- Never add `-A`, and never use `accept-new`. A changed host key is an error state.
- Run ssh with the person's environment (`SSH_AUTH_SOCK`).
- Respect their `ConnectTimeout`.
- Don't pre-probe TCP when ProxyJump or ProxyCommand is set.

### Versions
- `Wire.version` becomes `generation` plus `features: [String]` in both hellos. An unknown generation gets a typed rejection, and the app shows "needs update" (herdr).
- Within a generation, changes are additive only. The decoder skips unknown message cases (decode the discriminator first, then drop the case with a log line). Synthesized Codable throws on unknown cases today.
- No exact-version lock (VS Code, Zed and Warp have one): the Mac and iOS release trains will skew.
- Binaries go side by side in `~/.axolotty/bin/<version>/<os>-<arch>/`, with a `current` link.
- An upgrade restarts `axolottyd`, and ptyd keeps the PTYs. ptyd is never restarted silently.

### Install
- The Mac app bundles macOS universal, `linux-x86_64-musl` and `linux-aarch64-musl` binaries, plus a SHA-256 manifest.
- Detect with `uname -sm`, using literal `case` arms (BusyBox).
- Upload over the master: `cat > tmp`, check size and SHA, `tmp --version`, `chmod`, `mv`. No curl, wget or SFTP is needed, so it works air-gapped.
- Ask before the first install.

### Linux port
- Build with the Swift Static Linux SDK. musl static means no glibc floor (VS Code needs ≥ 2.28, Warp ≥ 2.31).
- `AxSys` reads `/proc` instead of `libproc`.
- ptyd moves from kqueue to poll or epoll.
- Socket at `$XDG_RUNTIME_DIR/axolotty`, mode 0700. Mind the `sun_path` length limit.
- logind `KillUserProcesses`: offer `systemd-run --user --scope` or `loginctl enable-linger`, but don't block on polkit.
- libghostty-vt needs a `*-linux-musl` build. Not checked yet.

### Reconnect
- Heartbeat on the existing ping/pong: every 5 s, dead after 15 s.
- On a dead link, kill the old ssh instead of waiting for it.
- Redial at once, then back off from 250 ms to 30 s with jitter.
- Redial on wake and when the network path changes.
- Input during a gap is dropped, not queued. The pane shows "Reconnecting…". A queued `y⏎` could answer a different prompt.

### Latency
- One round trip per key, with server-side echo.
- Measure the RTT and show it.
- Keys go in small frames of their own.
- Phase 2: predictive echo, only at ≥ 50–100 ms RTT, only on shell input lines (after OSC 133 B), never inside agent TUIs.

### UI
- **Sidebar.** Group by host only when there's more than one.
  - "This Mac" first, then each host under its ssh-config nickname.
  - A state dot plus text: connecting, connected, reconnecting in Ns, needs login, unreachable, needs update.
  - A "+" starts a session on that host.
  - Wherever a remote pane is named out of context (attention, notifications), it gets a `host/…` prefix.
- **Window.** A host chip for the focused pane's host. Its menu:
  - Connect to Host… (recent hosts, plus `ssh -G`-resolved Host entries, skipping wildcards);
  - Reconnect;
  - Disconnect;
  - Update Server;
  - Show Log.
- **Disconnected pane.** The last frame stays, dimmed, with a "Reconnecting… / Reconnect Now" bar.
- **Later:** port forwarding through the master (`ssh -S ctl -O forward -L …`).

## (b) Reach this Mac

1. **Free with (a).**
   - `ssh mac-studio axolotty bridge` from another Mac.
   - Any phone ssh client (Termius, Blink) can run `axolotty attach`.
   - Off the LAN it needs Remote Login plus Tailscale.
   - No new listener.
2. **iOS client.**
   - Over swift-nio-ssh exec of `axolotty bridge` first. Later, an opt-in TLS 1.3 listener with pinned device keys and QR pairing, bound only to the tailnet or LAN interface the person picks.
   - The UI is an attention list, then the pane.
   - Quick replies are guarded keystrokes: `key(pane, input, ifAt: offset)`. The server rejects one if the output has moved on since.
   - Push needs an APNs relay with end-to-end-encrypted payloads.
3. **Browser.**
   - libghostty-vt as wasm, plus a WebSocket listener behind Tailscale Serve (listening on localhost, with identity headers).
   - Never Cloudflare Tunnel: it decrypts every keystroke.

**Security:**
- Everything is off by default.
- Device roles: view, respond, full.
- A visible "remote client attached" indicator.
- A device list with revocation.
- A log of remote input.

## Ship order
1. **Protocol hardening:**
   - generation and features in hello;
   - tolerant decoding;
   - heartbeat;
   - a peer-uid check (`getpeereid` / `SO_PEERCRED`);
   - `HostEndpoint.command`.
2. **`axolotty bridge` with Mac→Mac over ssh:** the login pane, a private ControlMaster, upload, host groups and the host chip. This gives (a) for Mac hosts and (b) Mac-to-Mac.
3. **A static musl Linux host,** plus `--via` carriers (docker, kubectl).
4. **iOS client:** ssh first, then TLS pairing, then push.
5. **Predictive echo.**
6. **Browser client.**
